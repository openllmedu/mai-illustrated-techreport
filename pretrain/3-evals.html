Section 2.3

Evaluation Methodology

Why NLL over accuracy benchmarks, and how evaluation data is decontaminated

TL;DR

The team uses ~40 internal NLL (Negative Log-Likelihood) benchmarks across 5 categories (Code 50%, STEM 17.5%, Math 17.5%, General 10%, Multilingual 5%) instead of accuracy-based benchmarks. NLL is faster, more robust to formatting, and easier to construct. All training data is decontaminated against public benchmarks, and private benchmarks are used alongside.

NLL Over Accuracy

Instead of standard Q&A benchmarks (MMLUMassive Multitask Language Understanding — a popular benchmark with ~16,000 multiple-choice questions across 57 subjects (history, law, math, medicine, etc.). Often used to compare LLMs, but prone to data contamination.Learn more, MATH, etc.), the team primarily uses NLL (Negative Log-Likelihood)Measures how surprised the model is by the correct text. Lower NLL = the model predicted the actual text more accurately. Unlike accuracy, NLL doesn't depend on the model knowing answer formatting.Learn more evaluations — measuring how well the model predicts the next token in held-out text. Three reasons:

1. Speed and cost

NLL evaluation runs at training speed (just forward passes). Accuracy benchmarks require slow autoregressive generationGenerating text one token at a time, where each new token depends on all previously generated tokens. Much slower than forward-pass-only evaluation because the model must run sequentially — it cannot predict token #100 before generating tokens #1–99.Learn more and often a judge model to score. Lower cost = more evaluations per experiment = more reliable conclusions.

2. Robustness to formatting

Accuracy benchmarks are brittle — a model might know the answer but fail because it didn't write \boxed{} around it, or used \r\n instead of \n. NLL uses teacher forcingAt each prediction step, the model is conditioned on the actual correct text (not its own previous predictions). This prevents minor errors from snowballing.Learn more, so minor formatting differences don't compound into failures.

Example: A math benchmark asks "What is 7!?" The correct answer is 5040. Model A writes The answer is 5,040. — marked wrong because the benchmark expects \boxed5040. Model B writes \boxed5040 but doesn't understand factorials at all — just memorized the format. NLL avoids this entirely: it measures how well each model predicts a held-out document about factorials, regardless of how the answer is formatted.

3. Easier to construct

Any topic-relevant text can serve as an NLL evaluation. Building a good Q&A benchmark requires extensive calibration, difficulty tuning, quality control, and coordination with domain experts across multiple iterations.

Evaluation Suite

~40 benchmarks across 5 categories, combined into a single objective with explicit weights:

CategoryWeightExample Sources
Code50%Internal Microsoft code, pull requests, human-AI coding sessions
STEM17.5%Vendor-commissioned graduate-level STEM worked solutions
Math17.5%Vendor-commissioned advanced math worked solutions
General Knowledge10%Online forums, trivia databases, human-AI interactions
Multilingual5%Internal multilingual human-AI interactions

The heavy code+STEM+math weighting (85%) reflects the model's target use cases for reasoning.

DecontaminationThe process of removing evaluation/benchmark data that has leaked into training data. Without decontamination, a model might score well on benchmarks simply by memorizing leaked answers rather than actually understanding the material.Learn more

Public benchmarks increasingly leak into training data — especially via GitHub repos containing benchmark datasets with solutions. The team applies:

  • Remove all huggingface.co data and mirror domains
  • 20-gram fuzzy deduplication at 80% similarity threshold against known benchmarks
  • Private proprietary benchmarks developed in-house that can't leak because they've never been published
The team found that contamination can produce counterintuitive results — e.g., data meant to improve coding also improving long-tail general knowledge scores, because leaked benchmark examples for various topics were mixed into coding repositories on GitHub.
NLL evaluations provide faster, more robust, and more reproducible feedback than accuracy benchmarks during pre-training development. The team supplements them with private benchmarks to avoid contamination from public data leakage.
