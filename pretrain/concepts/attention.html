Attention Mechanisms

How MAI-Base-1 uses local/global periodic attention and GQA to balance quality and efficiency

TL;DR

Attention lets each token "look at" other tokens to understand context. MAI-Base-1 uses periodic local/global attention (5:1 ratio) to cut costs, Grouped-Query Attention (8 KV heads) to shrink inference memory, and no position encoding on global layers.

What Is Attention?

In a sentence like "The bank by the river was flooded," the word "bank" could mean a financial institution or a riverbank. Attention is the mechanism that lets the model look at other words ("river," "flooded") to figure out which meaning applies.

Technically, for each token, the model computes three vectors from the same input via separate learned projections:

  • Query (Q) — "what am I looking for?" Each token generates a Q vector that encodes what context it needs. "bank" might ask: "I am an ambiguous noun — what is my environment?"
  • Key (K) — "what do I advertise?" Each token's K vector describes what it offers. "river" advertises: "I describe natural terrain."
  • Value (V) — "what content do I share?" The actual information read when someone attends to this token. Keys are for matching; values are for reading. A book titled "Geography" (Key) contains information about rivers (Value).

The attention formula: Attention(Q, K, V) = softmax(Q x K^T / sqrt(d_k)) x V

  • Q x K^T — dot product of each Q with every K. High score = relevant match. Produces an [n x n] score matrix.
  • / sqrt(d_k) — scale down so no single match dominates. Without this, large dot products push softmax to a one-hot distribution. In MAI-Base-1, d_k = 128, so divide by ~11.3.
  • softmax — convert scores to weights summing to 100%. "bank" might put 40% on "river," 25% on "flooded," 15% on itself.
  • x V — weighted sum of V vectors. "bank" absorbs 40% of V_river + 25% of V_flooded + ... The output is "bank" infused with riverbank context.
In a causal decoder model generating "The cat sat on," when producing the next token: Q comes from "on" (the current token), K and V come from all previous tokens including "on" itself. The model computes Q_on dot K_The, Q_on dot K_cat, Q_on dot K_sat, Q_on dot K_on. If "sat" scores highest (say 50%), the output is dominated by V_sat's content. Q is used once and discarded; K and V are stored in the KV cache for all future tokens to attend to.

Multi-Head Attention

A single attention computation can only focus on one type of relationship. Multiple heads let the model look for many patterns simultaneously. MAI-Base-1 has 80 query heads — the model splits the embedding into 80 smaller pieces, runs attention on each independently, then concatenates the results.

Research has identified specific head types that emerge during training:

  • Previous Token Heads (early layers) — always attend to position i-1, providing "what came before" signal
  • Induction Heads (mid layers) — pattern-match: if [A][B] appeared before and [A] appears again, predict [B]. The core mechanism behind in-context learning
  • Duplicate Token Heads — detect when the same token appeared earlier, helping track references
  • Copy Suppression Heads — prevent the model from naively copying tokens, writing opposing signals to suppress repetition

Local vs. Global Attention

The quadratic cost is the key bottleneck. MAI-Base-1's solution: most layers only look at nearby tokens.

Local Attention (5 out of every 6 layers)

Each token only attends to the nearest 512 tokens (sliding window). Cost is O(n × 512) instead of O(n²). Uses RoPERotary Position Encoding — encodes relative positions by rotating query and key vectors. Base frequency 10,000. Allows the model to understand word order within the local window.Learn more (Rotary Position Encoding) with base frequency 10,000.

Global Attention (every 6th layer)

Each token attends to all tokens in the sequence. Uses no position encoding — found to perform comparably to RoPE while being more efficient. This is where the model connects information from distant parts of the input.

This 5:1 ratio (from Gemma 3) significantly reduces both training compute and KV cacheDuring inference, the model stores the key and value vectors for all previously generated tokens. The KV Cache: Why Inference Gets Expensive

During autoregressive generation, the model produces tokens one at a time. Each new token needs to attend to all previous tokens. Without caching, generating token #1000 would re-compute keys and values for all 999 preceding tokens — wasting massive compute. The KV cache stores each token's K and V vectors when first computed, so they are reused for every future token.

The tradeoff: KV cache saves compute but costs memory. For MAI-Base-1 at 256K context:

  • Global layers (13 layers): 8 KV heads x 2 (K+V) x 128 dims x 256K tokens x 2 bytes (FP16) = 0.52 GB per layer, 6.8 GB total
  • Local layers (65 layers): Only cache the last 512 tokens per layer — 8 x 2 x 128 x 512 x 2 = 1 MB per layer, 65 MB total
  • Total: ~6.9 GB — vs ~69 GB if all layers used full MHA with 80 KV heads globally
This is why MAI-Base-1's architecture choices compound: GQA (10x fewer KV heads) x local attention (512 vs 256K for 83% of layers) = roughly 100x KV cache reduction vs a naive MHA global-attention design. Without these optimizations, serving 256K context would be impractical on current hardware.

Attention Failure Modes

Understanding what can go wrong helps explain MAI-Base-1's design choices:

  • Attention dilution: On very long contexts, attention weights spread thin across thousands of tokens. Important information in the middle of a long prompt may receive too little weight — the "lost in the middle" phenomenon. MAI-Base-1 mitigates this with local attention windows that keep focus concentrated.
  • Positional degradation: Models trained on shorter sequences can perform poorly when extended to longer ones. RoPE helps with relative position encoding, and the long-context extension phase (Section 2.6) progressively trains on longer sequences.
  • Quadratic cost: Attention cost grows as O(n^2 x d). Doubling context from 32K to 64K roughly quadruples attention compute. Local attention makes this O(n x window_size x d) for 83% of layers.

Grouped-Query Attention (GQA)

Standard multi-head attention has separate K and V projections for every attention head. GQA shares K and V across groups of heads:

  • MAI-Base-1: 80 query heads but only 8 KV heads (10:1 ratio)
  • Per-head dimension: 128
  • KV cache is 10x smaller than standard multi-head attention
  • Quality is preserved because the Q heads can still attend to different things — they just share the K/V representations
Memory savings in practice: For a 256K-context global attention layer, standard multi-head attention (80 KV heads) would need 80 × 2 × 128 × 256K = 5.2 GB of KV cache per layer. With GQA (8 KV heads), that drops to 0.52 GB per layer. Across 13 global attention layers, that's 67 GB saved — the difference between fitting on one GPU or needing two.

Additional Details

  • QK-Norm: RMSNorm applied to queries and keys before computing attention scores, for training stability at scale
  • FlashAttention-4: Used for efficient GPU implementation, with Ulysses-style context parallelism for long sequences
  • Zero initialization: Attention output starts at zero (via zero RMSNorm gains), so the model initially processes tokens independently. Cross-token attention interactions emerge gradually during training, preventing early-stage MoE expert imbalance.
