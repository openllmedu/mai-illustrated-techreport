Evaluation Methodology Details

STEM: Math & Science

AIME and HMMT answers are simple numbers or expressions. The model outputs its answer in boxed format, enabling regex-based extraction followed by SymPyA Python library for symbolic mathematics. Used here to verify that extracted answers are mathematically equivalent to the ground truth, handling cases where the same answer can be expressed differently (e.g., ½ vs 0.5 vs 1/2).Learn more verification, with an AI judge (GPT-5-mini) as fallback. GPQA Diamond uses 198 multiple-choice questions with pass@1 averaged over 16 rollouts.

Agentic Coding

All three benchmarks use a simple, ReAct-style always-append agent loop: at each turn the model generates tool calls, the environment executes them and appends output, then the model makes the next call. Evaluation uses 256K context length with a maximum of 1,000 steps:

Safety Benchmarks

AIR-Bench evaluates policy-grounded refusal across regulatory harm taxonomies. CyberSecEval 4 tests whether the model produces vulnerable code — the Instruct benchmark presents requests designed to elicit insecure patterns, while Autocomplete prompts with code context leading up to a known insecure pattern.

Honesty & Health

TruthfulQA evaluates resistance to popular misconceptions (multiple-choice setting). LongFact measures factual precision over longer generations with claim-level extraction and LLM judge scoring. HealthBench Professional assesses health conversations using physician-created rubrics, with a length penalty to correct for LLM-grader bias toward longer responses. MedXpertQA uses 2,450 expert-curated multiple-choice questions (10 choices each) with GPT-5.4 answer extraction.

Tool Calling

BFCL v3 benchmarks function-calling across single-turn, parallel, multi-function, and multi-step agent scenarios. For determinism: T=0.001, p=0.97 as recommended by the official leaderboard.

Evaluation Framework: What Good Evaluation Looks Like

Evaluating an LLM is fundamentally different from evaluating a traditional software system. Good evaluation requires three layers:

Task Performance

Accuracy on target tasks (AIME, SWE-bench), format compliance, latency measurements, and edge case handling. This is what most benchmarks measure — but it's only one-third of the picture.

Regression Checks

Every improvement in one area risks degrading another. Evaluating safety, general reasoning (MMLU), code generation, and factual accuracy alongside the target task catches regressions that task-only evaluation misses. MAI monitors all dimensions continuously during every RL climb step.

Comparison Baselines

Raw scores are meaningless without context. MAI compares against: the pre-RL base model (to measure the RL delta), the previous best checkpoint (to confirm forward progress), and competitive frontier models (to establish relative standing). The comparison must include the cheapest non-fine-tuned alternative to confirm the training investment was worthwhile.

The MRCR benchmark is a cautionary example of evaluation fragility. MAI-Thinking-1 scores 60% on this long-context benchmark without targeted training. But when the team trained a smaller model on just 1,000 synthetic in-distribution examples, it scored 90%+. The benchmark wasn't measuring long-context capability — it was measuring exposure to a specific data pattern. This is why the team maintains private, unpublished benchmarks alongside public ones.
