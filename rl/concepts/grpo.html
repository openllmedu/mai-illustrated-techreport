GRPO & Adaptive Entropy Control

How Group Relative Policy Optimization avoids value networks, and how adaptive entropy keeps training stable.

The Post-Training Pipeline

Pre-training produces a capable base model — but it just autocompletes text. It won't answer questions, follow instructions, or reason step-by-step. The post-training pipeline transforms this raw capability into a useful assistant through three phases:

  1. SFT (Supervised Fine-Tuning) — Train on human-written (instruction, response) pairs to teach the Q&A format. The model learns to behave as a helpful assistant rather than a text continuation engine.
  2. Reasoning RL (GRPO) — RL on math/code with verifiable answers. This is where the model learns to "think step-by-step" via chain-of-thought. The reward is objective: did the answer match the ground truth? This is the core of MAI's RL climb.
  3. Alignment RL (RLHF/DPO) — RL from human preferences. Humans rank model outputs to train helpful, harmless, honest behavior.

This order matters. Pre-training sets the ceiling of what the model can do. Post-training determines the accessibility — whether users can actually get the model to do useful things. The InstructGPT result is striking: a 1.3B-parameter aligned model was preferred by humans over an unaligned 175B model — not because post-training is more important, but because without it the larger model's capability was inaccessible.

What Problem Does GRPO Solve?

Standard RL algorithms for LLMs (like PPO) need a separate "value network" that estimates how good each state is. This value network has its own parameters, needs its own training, and adds significant complexity. For a 962-billion-parameter model, maintaining a separate value network is extremely expensive — it effectively doubles memory requirements.

GRPO eliminates the value network entirely. Instead of estimating absolute state values, it uses the relative performance within a group of responses to compute advantages. This halves memory compared to PPO while achieving comparable or better results.

GRPO is now the dominant algorithm for reasoning RL across frontier labs. Its key insight: for tasks with verifiable answers (math, code), you don't need a learned reward model — just check if the answer is correct. The group comparison provides natural baselines without needing to estimate state values.

How GRPO Works, Step by Step

  1. Sample a group: For a given prompt, generate G=128 responses from the current model
  2. Score each response: Use the reward function to assign each response a scalar score
  3. Compute advantages: For response i with reward R_i, the advantage is:
    A_i = (R_i - mean(R_1...R_G)) / std(R_1...R_G)
    This normalizes rewards within the group, making the scale irrelevant.
  4. Update the model: For each token in each response, compute the probability ratio between the new and old policy. Multiply by the advantage and clip to stay within the trust region.
Concrete example with G=4 (simplified): Given the prompt "What is 7x8?", the model generates: "56" (correct), "54" (wrong), "56" (correct), "48" (wrong). Rewards: [1, 0, 1, 0]. Mean=0.5, std=0.5. Advantages: [+1, -1, +1, -1]. The model increases the probability of tokens that led to "56" and decreases those that led to "54" and "48".

Why Entropy Matters

During RL training, two failure modes threaten the model:

  • Entropy collapse — The model becomes too confident, always producing the same response. It stops exploring and can't discover better strategies. Once collapsed, recovery is nearly impossible.
  • Entropy explosion — The model becomes too random, producing incoherent outputs. Training signal becomes noisy and uninformative.

The Adaptive Controller

MAI's solution is an integral controller that adjusts the upper clip bound dynamically:

  1. Set a target entropy H* = 0.3
  2. At each step, estimate the current entropy from the training batch
  3. If entropy < H*: increase k (wider clip bound = more exploration allowed)
  4. If entropy > H*: decrease k (tighter clip bound = more conservative updates)
  5. k is bounded between 0 and k_max = 2.5

The controller starts at k=0 (symmetric clip bounds) and adapts from there. The step size delta=0.25 means k changes by at most 0.25 per training step.

The adaptive entropy controller acts as an automatic thermostat for exploration. Without it, the team would need to manually monitor entropy and tune clipping bounds — impractical for training runs lasting weeks.
