Section 3.1

RL Recipe

The core algorithm, rewards, and training strategy behind reinforcement learning for reasoning.

TL;DR

MAI uses GRPO with two key innovations: adaptive entropy control (auto-adjusts exploration vs. exploitation) and an outer ratio clip (prevents gradient spikes). Rewards combine task correctness, language consistency, and a difficulty-aware length penalty. Self-distillation lets the team carry forward progress across crashes, model updates, and instabilities.

The Core RL Objective

The RL climb starts from a pre-trained model (the "policy") and improves it by having it generate many candidate responses to each problem, scoring them, and then updating the model to produce more responses like the high-scoring ones.

The algorithm is based on GRPOGroup Relative Policy Optimization — a reinforcement learning algorithm where the model generates a group of responses to each prompt, scores them, and uses the relative ranking within the group (not absolute scores) to compute advantages. This avoids needing a separate value network.Learn more (Group Relative Policy Optimization). Here is how it works:

  1. For each prompt, the model generates a group of G responses (typically G=128)
  2. Each response gets a scalar reward (from code execution, a judge, or a reward model)
  3. Rewards are normalized within the group to produce advantagesA measure of how much better or worse a specific response is compared to the group average. Positive advantage = better than average, negative = worse. The advantage is shared across all tokens in the response — every word in a good answer gets credit.Learn more: how much better/worse than average each response is
  4. The model is updated to increase the probability of high-advantage responses and decrease low-advantage ones

The update is constrained by a trust regionA constraint on how much the model can change in a single update. Without it, the model might make huge jumps that destroy previously learned capabilities. The trust region ensures gradual, stable improvement by clipping the ratio between new and old probabilities.Learn more — the model can only change a limited amount per step, preventing catastrophic forgetting.

Deep dive: GRPO & Adaptive Entropy

Two Crucial Modifications

The team found that vanilla GRPO was unstable for long training runs. They added two modifications:

1. Adaptive Entropy Control

EntropyA measure of how "spread out" the model's probability distribution is over possible next tokens. High entropy = the model considers many options roughly equally likely (more exploration). Low entropy = the model strongly favors a few tokens (more exploitation). Entropy collapse = the model becomes too confident and stops exploring.Learn more measures how diverse the model's outputs are. Too low = the model becomes repetitive and stuck. Too high = outputs become random and incoherent.

Instead of manually tuning a fixed clipping bound, the team built an automatic controller that dynamically adjusts the upper clip bound based on the model's current entropy. When entropy drops too low, the controller widens the clipping to allow more exploration. When entropy is too high, it tightens to stabilize.

Figure 13 — Adaptive Entropy Control

Top: the model's entropy over 800 RL steps, hovering near the target of 0.3. Bottom: the controller parameter k adjusts automatically — decreasing when entropy is too high, increasing when too low.

What does adaptive entropy look like in practice? Suppose the target entropy is 0.3. At step 200, the model's entropy drops to 0.15 (it's becoming too confident). The controller increases k from 0.2 to 0.45 over the next 50 steps, widening the clip bound so the model can explore more diverse responses. By step 300, entropy has recovered to 0.32, and k stabilizes.

2. Outer Ratio Clip

Standard PPOProximal Policy Optimization — a popular RL algorithm that clips the ratio between new and old policy probabilities to prevent too-large updates. GRPO is a variant that uses group-relative advantages instead of a learned value function.Learn more-style objectives leave certain cases unclipped — specifically, when the model corrects itself in the right direction (e.g., reducing probability of a wrong answer or increasing probability of a right one). In theory this helps learning, but in practice it caused catastrophic gradient-norm spikes.

The fix: add a hard outer clip that applies to all branches, discarding any update where the old-to-new probability ratio is extreme (above rmax=50).

The two modifications (adaptive entropy + outer clip) together enable stable RL training over thousands of steps without manual intervention — critical for training runs lasting weeks.

Reward Design

Every RL response is scored by three components, combined into a single scalar reward:

Task Reward (Rtask)

The domain-specific signal. For math: is the extracted answer correct (verified with SymPyA Python library for symbolic mathematics. Used to check whether the model's answer is mathematically equivalent to the ground truth — so "2/4" and "0.5" and "1/2" all count as correct.Learn more)? For coding: do the tests pass? For helpfulness: what does the reward model say?

Language Consistency Reward (Rlang)

Penalizes foreign-language tokens appearing in the model's chain of thought. As context lengths grow during RL, models start mixing in non-English words, which correlates with training instability. Each non-English word in the reasoning trace receives a small penalty (alpha=0.005 per word).

Length Penalty (Rlen)

Penalizes unnecessarily long responses, but scaled by problem difficulty. Easy problems (high pass rate) get stronger penalties to encourage conciseness. Hard problems (low pass rate) get weaker penalties, giving the model room for longer reasoning.

How the length penalty adapts to difficulty: A problem with a 90% pass rate (easy) has rho_q = 0.9 and the penalty is 0.9 x (response_length / 128k). A problem with a 10% pass rate (hard) has rho_q = 0.1, so the same-length response gets 9x less penalty. Hard problems can "think longer" without being punished.

Sampling Strategy

Not every problem is worth training on. The team uses a two-stage filter to focus compute on problems at the right difficulty level:

Stage 1: Early Exit

Sample 16 quick responses. If the pass rate is outside [5%, 80%], discard the problem entirely. Problems that are too easy (everyone solves it) or too hard (nobody solves it) provide little learning signal.

Stage 2: Full Rollout

If the early check passes, generate all 128 responses. Apply a second pass-rate filter [10%, 80%]. Only problems with meaningful variance in success/failure are used for training.

Length Curriculum

Training starts with a max output length of 8k tokens, then doubles through 16k, 32k, 64k, up to 128k tokens. Early in training, the model doesn't need long reasoning traces, so shorter caps save enormous inference cost. As the model improves and tackles harder problems, longer traces become necessary.

The team uses top-p samplingAlso called nucleus sampling. Instead of considering all possible next tokens, only tokens whose cumulative probability exceeds p (e.g., 0.97) are considered. This filters out extremely unlikely tokens while preserving diversity. The team stores the top-p mask and replays it during training to prevent numerical divergence.Learn more with p=0.97 and found that without replaying the sampling mask during training, the model can diverge catastrophically within a few steps.

Self-Distillation

Long RL climbs (thousands of steps over weeks) face practical challenges: crashes, numerical instabilities, and the need to update the base model mid-run. Self-distillationA technique where the model learns from its own outputs. Collect good reasoning traces from the RL run, then train a fresh copy of the base model on those traces via supervised learning. The resulting model becomes the new starting point for continuing RL.Learn more addresses all of these.

The process: collect successful reasoning traces generated during RL, and use them to train a fresh mid-trained checkpoint via SFTSupervised Fine-Tuning — standard next-token-prediction training on curated (input, output) pairs. Unlike RL which uses rewards and exploration, SFT directly teaches the model to reproduce specific outputs. Faster and more stable than RL, but less flexible.Learn more (supervised fine-tuning). This new model becomes the starting point for continuing the RL climb.

Deep dive: Self-Distillation

Key Findings

  • About 1 million reasoning traces are sufficient to match teacher performance — more provides diminishing returns
  • Including traces from later stages of the climb is critical; early-stage traces hurt performance
  • Using traces from multiple checkpoints (not just the final one) provides diversity that helps subsequent RL exploration
  • Prompt diversity matters more than multiple traces per prompt
  • High dropoutA regularization technique that randomly disables neurons during training. At 0.15 rate, 15% of neurons are turned off each training step. During self-distillation, high dropout increases output diversity and prevents the model from becoming too narrow, which helps subsequent RL stages.Learn more (0.15) during self-distillation increases entropy and prevents model collapse
