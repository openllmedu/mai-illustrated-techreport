Helpfulness & Safety Climb

Teaching the model to be helpful, safe, honest, and well-written through human preference learning.

TL;DR

The helpfulness climb uses three reward types: a human-preference reward model (cyclic scoring for fairness), AI judges (fast, adaptable feedback), and verifiable rewards (unhackable constraint checking). Safety uses gated rewards where policy compliance is non-negotiable. Honesty training penalizes confident hallucinations most heavily. Style grading uses coarse scales to resist gaming.

Overview

Unlike STEM and agentic tasks (where correctness is objectively verifiable), the helpfulness and safety climb optimizes for subjective qualities: Is the response helpful? Does it follow instructions? Is it safe? Honest? Well-written?

This requires a fundamentally different reward strategy: instead of binary correct/incorrect signals, the team uses a combination of human preference models, AI judges, and verifiable constraints.

Reward Signals

1. Reward Model

A fine-tuned version of MAI-Base-1 that predicts human preferences. Trained on human-annotated side-by-side comparisons where annotators rated responses on a 1-5 scale.

The reward model uses a clever inference trick: for a set of candidate responses, it evaluates them in all possible orderings (cyclic permutations) and only uses the first-position score from each ordering. This reduces noise from autoregressive position effects.

Cyclic reward model scoring: Given 4 candidate responses A, B, C, D, the model runs 4 times: (A,B,C,D), (B,C,D,A), (C,D,A,B), (D,A,B,C). From each run, only the first token's probability distribution is used. This means each response gets scored exactly once in the privileged first position, ensuring fair comparison.

2. AI Judge

A prompted LLM that provides rubric-guided feedback. AI judges can be adapted quickly to target specific behaviors without waiting for reward model retraining. They provide a fast lever for shaping model behavior in targeted ways.

3. Verifiable Rewards

For instruction followingThe model's ability to adhere to specific constraints in the user's request: 'respond in exactly 3 paragraphs', 'use no more than 50 words', 'format as JSON'. These can be verified programmatically, providing clean training signal.Learn more constraints that can be checked directly (e.g., "respond in a single paragraph", "use fewer than 10 words"), rule-based verifiers provide clean, unhackable rewards. These are less prone to reward hackingWhen a model finds shortcuts to maximize its reward score without actually solving the task. For example, an AI judge that rewards longer responses can be hacked by producing verbose, repetitive text. Verifiable rewards are harder to hack because they check specific, concrete properties.Learn more than AI-based rewards.

Combining Rewards Safely

A critical challenge: how to combine rewards of different types and scales without letting one dominate? The team uses two complementary strategies:

Lexicographic Reward Shaping

Lower-priority rewards only matter when all responses in the group score equally on higher-priority rewards. Safety comes first — helpfulness only influences the gradient when all responses are equally safe. This avoids needing to calibrate reward scales.

Gated Reward Application

Higher-priority rewards must meet a minimum threshold before lower-priority rewards are applied at all. An unsafe response receives the minimum reward regardless of how well-written it is — quality never trades off against safety.

Both strategies avoid the need for cross-scale calibration. Safety is never traded for helpfulness — an unsafe but eloquent response always scores at the minimum.

Instruction Following

Training covers formatting constraints (paragraph count, word limits), behavioral constraints (tone, formality), and conflicting instructions (system vs. user vs. developer messages). The model must learn instruction hierarchy — whose instructions take priority when they conflict.

Data comes from two sources:

  • Expert-written contexts with complex, layered constraints that bootstrap capabilities
  • Synthetic data generated via a pipeline that creates realistic instructions, scenarios, and evaluation rubrics covering 40+ domains

Difficulty is controlled via pass-rate analysisA technique for calibrating training data difficulty. Generate multiple model responses to each prompt and measure what fraction succeed. Keep only prompts where the model succeeds sometimes but not always — these provide the most learning signal. Too-easy or too-hard prompts are filtered out.Learn more — only prompts that are challenging but solvable are retained.

Safety

Safety training targets two failure modes:

  • Unsafe compliance — The model fulfills a harmful request it should refuse
  • Over-refusal — The model unnecessarily refuses a legitimate request

Training data includes:

  • Harmful prompts — From human red-teaming and automated adversarial generation (PyRITPython Risk Identification Toolkit — a Microsoft tool for automated red-teaming of AI systems. Generates template-based attacks to test model safety boundaries.Learn more, PAPPersuasive Adversarial Prompts — attack prompts designed to use persuasion techniques (social proof, authority, emotional appeal) to bypass safety guardrails.Learn more, TAPTree of Attacks with Pruning — an adaptive attack method that uses a search tree to iteratively refine jailbreak prompts. More sophisticated than single-shot attacks because it adapts based on the model's responses.Learn more)
  • Borderline prompts — Sensitive but legitimate requests where the model should not refuse

The safety reward uses a gated approach: policy compliance is checked first. A non-compliant response gets minimum reward regardless of all other qualities.

Honesty

Honesty training teaches the model to be correct when it knows the answer and to hedge appropriately when it doesn't — without over-hedging (which reduces informativeness). The data spans:

  • Established facts — Short and long-form questions with verifiable reference answers
  • Challenging facts — Long-tail or obscure topics where the model may be inconsistent
  • False-premise queries — Questions containing incorrect assumptions where no correct affirmative answer exists

The reward uses five categories: Confident_Correct (highest reward), Unconfident_Correct (reduced — to discourage over-hedging), Not_Attempted (neutral), Unconfident_Incorrect, and Confident_Incorrect (steepest penalty — confident hallucinationsWhen a model generates claims that sound confident and plausible but are factually incorrect. Unlike human errors, hallucinations are particularly dangerous because the model's confident tone makes them hard to detect without fact-checking.Learn more are the worst outcome).

Style

A style guide specifies what good outputs look like:

DimensionGuidance
ToneProfessional by default; playful only when asked
LayoutNo sycophantic intros ("Great question!"). Clear hierarchy. Important info up front.
DensityNo walls of text. Strategic bold. Short sentences.
Tables/listsUse for multiple points, examples, or data — not for single items
EmojisMinimal — only in clearly casual contexts, never as headers

Style graders use coarse 3-point scales (0=major issues, 1=minor, 2=none). The team found that coarse graders outperform fine-grained rubrics because they give the judge more flexibility, making them harder for the model to game.

Constraint Taxonomy

The team built a detailed taxonomy to organize the types of instructions a model may be asked to follow. It serves two purposes: guiding data collection toward broad coverage (including rare constraint combinations) and enabling fine-grained performance analysis.

Objective (Hard) Constraints

These are rule-based constraints checked by Python functions from a catalog of custom and open-source checkers:

TypeExamples
NumericalLength limits, sentence/paragraph counts, item counts, range constraints, ratios
FormatDocument structure, lists, tables, code formatting, JSON/YAML serialization, templates, citation formats
ContentRequired/prohibited terms, required elements, source/citation requirements, temporal/geographic scope
LinguisticLanguage selection, dialect, register, sentence structure, parts of speech, grammar rules
Temporal/SequentialChronological ordering, procedural steps, alphabetical order
NegativeInstructions to exclude certain behaviors or formatting patterns

Subjective (Soft) Constraints

These need judgment to evaluate and are scored by the reward model or AI judges:

TypeExamples
StylisticTone, voice, vocabulary level, audience adaptation, emotional valence, brand voice
PersonaRole adoption, personality traits, values, emotional state
InteractionConversation navigation, certainty/hedging, clarification strategies, prosocial behaviors
ReasoningReasoning process requirements, argumentation structure, conditional branching, scope constraints
Instruction handlingConditionality, multi-step instruction chains, conflict handling
